# Titles are projects

Part of the backend guide, see [CLAUDE.md](../CLAUDE.md).

- A track is written with a `projectId`, not with a name: `POST /tracks` takes the title (`nameTitle` = the Ukrainian name) and the type from the project and ignores whatever the request says about them. The season is the one of the start date of the project unless the request names `season` and `year` together (both or neither), which may be any season up to the current one (a project can be entered long after the work), else 400. `nameTitle` stays on the track as a snapshot, because the audit texts and the old tracks use it; the lists and the lookups go by `projectId` (`GET /tracks?projectId=…`, `GET /tracks/last?projectId=…&episode=…`).
- After the tracks are saved, each nickname with its role is added to `participants` of the project (`ProjectsService.addParticipants`: the nickname is matched in any case and keeps the spelling the team has, the team stops at 50 and who does not fit is logged, a person who has the role already costs no write, at most two writes however many people the track has, and when another request puts the same new person there first it reads the team again, at most three times, and then answers 409). It only adds, deleting a track takes nobody off, and a failure there is logged and does not undo the track.
- `GET /projects/titles` is the list for a select: every project, the running ones first, the newest first. A track in the system means its episode is out, so `ProjectsService.markEpisodeReleased` raises `episodesReleased` of a series to the episode of every new track. It only raises, deleting a track does not lower it, and the curator can still correct the number by hand in the project form.
- `TracksModule` imports `ProjectsModule`, which does not import tracks, so there is no import cycle.
- `node dist/cli.js migrate:titles --dry-run` prints the plan, `migrate:titles` does it, and running it again changes nothing. Every title of `team_animes` and every `nameTitle` the tracks were written under becomes a project, unless a project already carries that name (ukrName, romajiName or codeName, any case) and then the tracks are only linked to it; two projects with one name are left for a person to decide. Names are the old name in both languages and the link is a search on MyAnimeList, all of it editable later. The episodes with tracks count as released: a new project starts with the newest of them, and a project that is there already is raised to it, never lowered. A title whose last track is older than the previous season (or, with no tracks, was added before it) becomes a finished project excused from the debt, the others stay running, and a running project that started before this season counts as a debt by the usual rule. A title is moved once: whatever the run makes a project of or links to one, its row in `team_animes` gets `projectId`, and a title whose tracks all have a project and whose row is marked (or that has no row) is skipped as `moved`, so a project that was renamed or deleted since is not made again. A track written the old way after that goes to the project the title went to (found by the mark or by its linked tracks). The team of a new project holds the 50 people with the most tracks, and the report says how many were left out. A track with no `createdAt` is dated by its `_id`. The plan is `seeds/titles-plan.ts`, and the collection `team_animes` is left in place.
